## 1. Сравнение механик категорий: Anki и аналоги

Исследование выполнено до этой сессии (данные ask); ключевые источники проверены 2 ноября 2026. Не проверено мной напрямую: исходный код Anki, SuperMemo knowledge tree (гайд закрыт anti-bot), поведение счётчиков Obsidian SR, AnkiMobile learning-счётчик (документация описывает только зелёный и синий).

### Anki (эталон)
- **Колоды с иерархией через `::`**: «Decks can contain other decks… Anki uses double colons (::) to show different levels within the deck tree» — docs.ankiweb.net/getting-started.html. Отдельной сущности подколод нет — дерево выводится из имён. **Факт.**
- **Обучение колоды ВСЕГДА включает подколоды**: «Study in Anki is limited to the currently selected deck as well as any subdecks it contains» — docs.ankiweb.net/studying.html. Отдельного режима «учить колоду без подколод» из списка колод у Anki нет; нюанс мануала лишь в том, что клик прямо по подколоде собирает очередь только из неё и её подколод (а клик по родителю — из всех потомков). **Факт — важно для §4: мы не изобретаем режим «без подкатегорий», его нет и у эталона.**
- **Три счётчика new/learning/due на каждом уровне**, агрегируются вверх — studying.html. **Факт.**
- **Теги — многие-ко-многим на заметке, колода — ровно одна на карточку**: «you can add several tags to a single note, but a single card can only belong to one deck» — editing.html. Мануал не советует плодить мелкие колоды: «it's a better idea to use tags and/or fields to classify your content». **Факт.**
- **Фильтрованные колоды** — временные подборки по поисковому запросу, карточка остаётся в «home deck» — filtered-decks.html. **Факт.**

### Аналоги (кратко)
- **RemNote**: папки содержат только папки/документы; Portals — ссылка на контент без перемещения. Для личного приложения сложность не нужна.
- **Mochi**: вложенные колоды + теги, режущие поперёк дерева (#food собирает из всех колод) + custom views (сохранённые фильтры).
- **Obsidian Spaced Repetition**: два взаимозаменяемых способа — путь папки = путь колоды ИЛИ иерархические теги `#flashcards/Languages/Kanji` (stephenmwangi.com/obsidian-spaced-repetition/flashcards/decks).
- **Quizlet**: Class → Folder → Study Set; социальный слой — для одного пользователя не нужен.
- **SuperMemo**: knowledge tree + learning queue с приоритетами (не проверено первоисточником).

### Вывод из сравнения
Во всех пяти продуктах повторяются: (1) вложенная иерархия, (2) агрегированные счётчики на каждом уровне, (3) «учить сегодня» одним действием сверху, (4) теги/умные подборки поверх иерархии, (5) недавнее/избранное (слабее всего). Но масштаб этих продуктов несопоставим с коллекцией из одной карточки на текущем скриншоте — см. §4 про пороги.

## 3. Рекомендуемая модель категорий

**Рекомендация: гибрид — плоский список колод (именованных категорий) + опциональная иерархия через `::` + плоские теги на заметке.** Один выбор, обоснование:

- **Колода (категория), ровно одна на карточку** — взаимоисключающий «дом» карточки, определяющий что и когда учить. Это семантика Anki (editing.html: «a single card can only belong to one deck»).
- **Иерархия — за порогом, не в базе итерации.** Именование `Математика::Интегралы` поддерживается форматом имени (Aggregation по префиксу — как Anki, getting-started.html), но UI итерации 1 — плоский список; дерево (раскрытие, отступы, «учить ветку») включается, когда категорий реально больше ~10 (см. вопрос 8.1). Для коллекции с одной карточкой на скриншоте трёхуровневое дерево с контекстными меню — оверинжиниринг.
- **Теги (массив строк на заметке)** — только для кросс-категорийной классификации и фильтров. Не влияют на расписание. В итерации 1 можно отложить (вопрос 8.2).
- **Идентификатор категории = имя.** Выбрано осознанно ради простоты снапшот-синка без отдельной таблицы; цена — необходимость явных rename-операций в синке (§4.6). Альтернатива (uid-сущности) отклонена как избыточная для одного пользователя; если пользователь в 8.3 выберет uid — §4.6 переписывается.
- **Валидация имён** (не определялось ранее — добавлено): имя обязательно и непустое; последовательность `::` в имени запрещена — поле ввода не даёт ввести второй `:` подряд (или предлагает замену на `›` с сохранением в имени как есть, без семантики); дубликат имени запрещён (ошибка «Категория с таким именем уже есть»); ведущие/хвостовые пробелы обрезаются; «Без категории» — зарезервированное отображаемое имя, ввести его нельзя.
- **Совместимость с Anki-экспортом (.apkg):** имя локальной колоды → имя колоды Anki; префикс `::` ожидаемо даёт вложенность — **гипотеза, требует эксперимента Э1** (экспорт минимального набора → импорт в десктопный Anki → проверка дерева и тегов; затем обратный импорт). Теги заметки → нативные теги Anki (метаданные заметки). Поле с именем `Deck` внутри нотетайпа запрещено (spec §2) — категория живёт вне полей. **Импорт из .apkg — за порогом итерации** (вопрос 8.4).

Ограничение фиксируется в модели явно: у карточки ровно одна колода (nullable → «Без категории»), у заметки массив тегов.

## 4. Конкретные изменения экранов

Масштаб итерации 1: **плоский список категорий, одна кнопка «Учить», чип категории на карточке, пикер в «+», категории в снапшоте.** Пункты, помеченные «за порогом», включаются при росте коллекции (критерий — вопрос 8.1: десятки категорий или явный запрос пользователя).

### 4.1 «Обучение» → главный экран категорий
Порядок блоков сверху вниз (замена текущей структуры):
1. **Кнопка «Учить: N к повторению»** — крупная, на всю ширину, вместо маленького ▶. На главном экране категория не выбрана — кнопка обучает **всю коллекцию** (все карточки с due). Под ней caption «+M новых».
2. **Список категорий** (плоский, алфавитный; в итерации 1 без дерева):
   - строка: имя, счётчик «к повторению» + суммарное число карточек (два числа, не три: «обучаются» в FSRS-терминах приложения сейчас не выделено — трицветная схема AnkiDroid откладывается до появления learning-состояния в UI);
   - тап по строке = обучение **этой категории и её подкатегорий, если появится иерархия** (семантика Anki studying.html: выбор колоды всегда включает подколоды; отдельного режима «без подкатегорий» нет и не вводим);
   - контекстное меню (long-press): переименовать, удалить (карточки → «Без категории» с подтверждением), переместить все карточки. Создание подкатегории и экспорт — за порогом;
   - «Без категории» — служебная секция внизу (аналог Default-колоды Anki: скрыта, если пуста и есть другие категории).
3. **«Все карточки»** — отдельный push-экран из таба «Обучение» (не новый таб): текущий плоский список со поиском; в шапке — чипы-фильтры по категории.
4. Поиск «Поиск по карточкам» на «Все карточки» дополнить фильтром по категории (scope-чипы).
5. Статистика «К повторению / Оценок / Последняя оценка» остаётся агрегатом по коллекции в итерации 1; разбивка по категориям — за порогом.

Определение счётчиков (не определялось ранее — добавлено): «к повторению» = карточки с due ≤ сейчас; «новые» = ни одного повторения в истории. Дневные лимиты FSRS per-категория в итерации 1 отсутствуют, поэтому лимиты на счётчики не влияют; когда появятся пресеты (§5), счётчик остаётся «всего due», а лимит применяется при сборе очереди.

### 4.2 Обзорный экран категории — за порогом
В итерации 1 тап по категории сразу запускает обучение (быстрее для одной карточки и десяти). Отдельный экран со счётчиками, хлебными крошками и списком карточек — при переходе порога 8.1. Формулировка снята из критики: у эталона Anki нет режима «учить без подколод», и мы его не вводим.

### 4.3 Карточка
- **Шапка:** тапабельный чип категории под заголовком (рядом с «Карточка»/«Закрыть») — тап открывает смену категории (плоское меню + «Без категории»). Пусто → «Без категории».
- **Сессия повторения (▶):** индикатор текущей категории над вопросом — единственное изменение; выбор охвата обучения живёт в точках входа (главный экран — вся коллекция; строка категории — эта категория), не в сессии.
- История повторений не трогаем. Попутно: `Locale.current` у форматтера даты (сейчас английская локаль — скриншот image-17472f…png).

### 4.4 Создание карточки («+»)
**Не проверено: скриншот диалога «+» не предоставлен** — ниже целевое поведение, сверить с фактическим диалогом при реализации.
- Поле «Категория» с дефолтом = категория, из контекста которой открыли «+» (из «Все карточки» — «Без категории»). Выбор через плоское меню. Не обязательное — «Без категории» легитимна (аналог Default-колоды).
- Редактирование карточки: тот же пикер. Теги — за порогом (вопрос 8.2).

### 4.5 Заметки — **требует скриншота/кода, в итерации не предписывается**
Экран «Заметки» не предоставлен, кода нет: наблюдений и предписаний по нему нет. Единственное модельное следствие (не UI): теги принадлежат заметке (модель Anki, editing.html), поэтому при реализации тегов они появятся в редакторе заметки, а не карточки. Пункт исключён из плана работ итерации 1.

### 4.6 Серверная модель, экспорт .apkg и синк
- **Схема снапшота** (ранее не задана — добавлено). Снапшот версии 2:
  ```json
  {
    "snapshot_version": 2,
    "deck_renames": [{"from": "Математика", "to": "Математика::Интегралы"}],
    "cards": [{"uid": "…", "deck": "Математика::Интегралы", "note": {"tags": []}}]
  }
  ```
  Верхнеуровневого массива `categories` **нет** — категория производная от имён (устраняет противоречие с §3); теги заметки — массив `tags` внутри note (если теги приняты в 8.2, иначе поле отсутствует). `deck` = "" или null → «Без категории».
- **Обратная совместимость:** снапшот без `snapshot_version` (старый, v1) принимается; отсутствие `deck`/`tags` трактуется как ""/[] — карточки попадают в «Без категории», данные не теряются.
- **Rename vs delete (устраняет риск потери данных):** локальное переименование ветки (когда появится иерархия; в плоской итерации — переименование категории) записывает операцию в `deck_renames` и отправляется со снапшотом. Загружающая сторона применяет rename ко всем `card.deck` с префиксом `from`, а не удаляет+создаёт. Категория считается удалённой только если она отсутствует в снапшоте **и** нет покрывающей rename-операции — тогда карточки падают в «Без категории» **не молча**: на экране «Конфликты» появляется запись «N карточек потеряли категорию X (удалена на другом устройстве)».
- **Конфликты rename×rename / rename×edit:** в итерации 1 не разрешаются автоматически — попадают в существующий экран «Конфликты» (механизм очереди мержей не меняем, меняется только состав payload). Семантика ручного снапшота («Отправить/Загрузить») сохранена — §6 соблюдён: критичный путь не трогаем, расширяем только payload.
- **Экспорт .apkg:** имя локальной колоды → имя колоды Anki; `::` в имени → вложенность (**гипотеза, эксперимент Э1 до реализации**); теги заметки → теги Anki. Импорт из .apkg — за порогом (вопрос 8.4).

## 5. Второй приоритет (после основной итерации)

1. **Две фиксированные подборки**: «К повторению сегодня» и «Недавно добавленное» (не произвольные custom views — оверинжиниринг). Карточка остаётся в своей колоде.
2. **Иерархия в UI**: раскрытие дерева по `::`, отступы, «учить ветку», создание подкатегорий, экспорт категории — при переходе порога 8.1.
3. **Обзорный экран категории** со счётчиками (всего/новые/к повторению/просрочено) и статистикой удержаний за 30 дней.
4. **Недавние/закреплённые категории** — чипы в 4.1.
5. **Пресеты параметров FSRS** (лимиты new/reviews per day) per-категория, «Save to All Subdecks» (паттерн Anki deck-options.html).
6. **Теги**: чирпы на заметке, фильтр по тегу, пользовательские фильтрованные подборки (аналог Anki filtered decks) — только после тегов.

## 6. Что НЕ делать в этой итерации

- **Не трогать сервер/синк-механику**: ручной снапшот, «Отправить/Загрузить», очередь мержей, конфликты — расширяется только payload (§4.6); rename-операции — минимальное исключение, без автомержа.
- **Не вводить дерево в UI** (раскрытие, drag-and-drop, контекстные меню подколод) — за порогом 8.1; иерархия имён `::` поддерживается форматом, но не обязательна.
- **Не делать обзорный экран категории, трицветные счётчики, произвольные сохранённые запросы** (Mochi custom views) — сначала две фиксированные подборки.
- **Не переносить расписание на теги** — теги не влияют на очереди.
- **Не делать импорт из .apkg** (только экспорт, после Э1), per-категорию опции расписания, режим «учить без подкатегорий» (его нет у эталона Anki).
- **Не менять** историю повторений, оценки FSRS, экран «Граф», §4.5 «Заметки» (нет данных для спецификации).

## 7. Порядок реализации (без сроков)

Если нет — добавить nullable `deck: String?` в карточку. Категории — производная от имён, отдельной таблицы нет.
2. **Экран «Обучение»:** перестановка блоков (кнопка «Учить: N» → плоский список категорий со счётчиком → push «Все карточки»), контекстное меню (переименовать/удалить/переместить).
3. **Карточка:** чип категории, смена категории, индикатор в сессии.
4. **Создание «+»:** сверить диалог с фактическим (скриншота нет), добавить пикер категории с дефолтом из контекста.
5. **Синк:** payload v2 по схеме §4.6, обратная совместимость v1, `deck_renames`, запись в «Конфликты» при потере категории.
6. **Валидация имён** по §3 (запрет `::`, дубликаты, пустые).
7. **Экспорт .apkg** — после эксперимента Э1 (экспорт→Anki→обратно, результат Э1 зафиксировать до кода).
8. **Полировка:** локаль даты (4.3), фильтр поиска по категории.
9. **За порогом** (по ответам 8.1–8.4): иерархия UI, обзорный экран, теги, подборки, пресеты FSRS.

## 8. Вопросы пользователю

Сформулированы только те, что не предрешены в спеке. Предрешено и вынесено из вопросов: идентификатор категории = имя + rename-операции в синке (§3, §4.6); кнопка «Учить» на главном экране = вся коллекция (§4.1). Если какой-то из этих выборов не устраивает — сказать, соответствующие пункты переписываются.

1. Сколько категорий планируется реально (до ~10 / десятки)? До ~10 — итерация 1 остаётся плоской; десятки — дерево и обзорный экран поднимаются из «за порогом» в итерацию 1.
2. Теги на заметках — делать в итерации 1 или отложить? От ответа зависит, включать ли `tags` в схему снапшота v2 сразу.
3. Идентификатор категории: имя + rename-операции (выбор спеки) — подтверждаете? Если нужен uid-вариант, §4.6 переписывается до реализации.
4. Нужен ли импорт из Anki (.apkg), или только экспорт наружу? Спека вынесла импорт за порог.
5. Эксперимент Э1 (.apkg туда-обратно) проводить вам на десктопном Anki до кода, или отдать как часть задачи реализации?
