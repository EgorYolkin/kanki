# UX приложения: итоговое состояние для ИИ-агента

Источник: ux-categories-spec.md (правка 2 по критике, 2 ноября 2026) + аудит 5 скриншотов.
Разделяй: **[Текущее]** — уже реализовано и работает; **[Изменить]** — целевое состояние итерации 1 по категориям; **[Запрет]** — трогать нельзя.

## Общая модель

- Таббар из 4 табов: **Обучение / Заметки / Граф / Настройки**. [Текущее]
- Карточка принадлежит **ровно одной категории** (аналог колоды Anki), поле nullable → «Без категории». Категория — производная от имени, **отдельной таблицы нет**. Иерархия поддерживается в имени через `::` (например `Математика::Интегралы`), но в этой итерации UI плоский.
- Теги — массив строк **на заметке**, не на карточке. Не влияют на расписание. В итерации 1 отложены (решить при старте работ).
- Идентификатор категории = имя. Переименование передаётся в синке операцией rename, не delete+create.
- Проверить при старте: существует ли в модели карточки поле `deck` (описано в anki-ios-mvp-spec.md, кодом не подтверждено). Если нет — добавить `deck: String?`.

## Экран «Обучение» (первый таб) [Изменить]

Порядок блоков:
1. **Кнопка «Учить: N к повторению»** — крупная, на всю ширину (вместо текущей маленькой FAB ▶). На главном экране категория не выбрана → обучает всю коллекцию. Caption под кнопкой: «+M новых».
2. **Плоский список категорий** (алфавитный): строка = имя + два счётчика («к повторению» и всего карточек). Счётчики: «к повторению» = due ≤ сейчас; «новые» = нет ни одного повторения. Тап по строке = обучение этой категории (и подкатегорий, если появится иерархия — семантика Anki: отдельного режима «без подкатегорий» нет и не вводим). Long-press: контекстное меню — переименовать, удалить (карточки → «Без категории», с подтверждением), переместить все карточки. «Без категории» — служебная секция внизу, скрыта, если пуста и есть другие категории.
3. **«Все карточки»** — отдельный push-экран: текущий плоский список карточек с поиском + чипы-фильтры по категории в шапке.
4. Статистика «К повторению / Оценок / Последняя оценка» — агрегат по коллекции, остаётся.

Счётчики — **два числа**, не трицветная схема AnkiDroid (learning-состояние в UI не выделено).

## Карточка [Изменить]

- Под заголовком рядом с «Закрыть» — **тапабельный чип категории**; пусто → «Без категории». Тап = смена категории (плоское меню + «Без категории»).
- **Сессия повторения:** индикатор текущей категории над вопросом. Выбор охвата обучения живёт только в точках входа (главный экран — вся коллекция; строка категории — эта категория), не в сессии.
- Вопрос / «Показать ответ» / Ответ / 4 оценки (Снова, Трудно, Хорошо, Легко) / История повторений / «Удалить карточку» — без изменений.
- Попутный фикс: дата в истории должна использовать `Locale.current` (сейчас английская локаль при русском UI).

## Создание карточки («+») [Изменить, сверить с фактическим диалогом — скриншота нет]

- Поле «Категория», дефолт = категория контекста открытия (из «Все карточки» → «Без категории»). Выбор — плоское меню. Необязательное.
- Валидация имён категорий: непустое; запрещён ввод `::` (не давать ввести второй `:` подряд); дубликаты запрещены («Категория с таким именем уже есть»); пробелы по краям обрезаются; имя «Без категории» зарезервировано, ввести нельзя.

## Настройки [Текущее, без изменений]

Тема (Системное/Светлое/Тёмное), Сервер (URL/токен/проверка/не подключён), Синк («Отправить на сервер» / «Загрузить с сервера», ручной снапшот, автомержа нет), Данные (JSON-экспорт в меню «Экспорт» раздела «Обучение»), Служебные экраны (Очередь мержей, Конфликты), Версия 0.1.0 / сборка 1.

## Синк и экспорт [Изменить: только состав payload, механику не трогать]

Снапшот версии 2:
```json
{
  "snapshot_version": 2,
  "deck_renames": [{"from": "Математика", "to": "Математика::Интегралы"}],
  "cards": [{"uid": "…", "deck": "Математика::Интегралы", "note": {"tags": []}}]
}
```
- Верхнеуровневого массива `categories` нет — категория производная от имён. `deck` = ""/null → «Без категории». `tags` включать только если теги приняты.
- **Обратная совместимость:** старый снапшот без `snapshot_version` принимается; отсутствие `deck`/`tags` = ""/[] — карточки в «Без категории», данные не теряются.
- **Rename vs delete:** переименование пишет операцию в `deck_renames`; загружающая сторона применяет rename ко всем `card.deck` с префиксом `from`. Категория считается удалённой только если её нет в снапшоте **и** нет покрывающего rename — тогда карточки падают в «Без категории» **не молча**: запись на экране «Конфликты» («N карточек потеряли категорию X (удалена на другом устройстве)»).
- rename×rename / rename×edit в итерации 1 не разрешаются автоматически → существующий экран «Конфликтов».
- **Экспорт .apkg:** имя категории → имя колоды Anki; `::` → вложенность (**гипотеза — сначала эксперимент Э1: экспорт → импорт в десктопный Anki → проверка дерева → обратный импорт**). Теги заметки → теги Anki.

## [Запрет] Не делать в этой итерации

1. Не менять механику синка: ручной снапшот, очередь мержей, «Отправить/Загрузить» — расширяется только payload (+ rename как минимальное исключение, без автомержа).
2. Не делать дерево в UI (раскрытие, отступы, drag-and-drop, меню подколод) — порог: десятки категорий.
3. Не делать обзорный экран категории, трицветные счётчики, произвольные сохранённые фильтры (custom views).
4. Не переносить расписание на теги; не делать импорт из .apkg; не делать per-категорию опции FSRS.
5. Не вводить режим «учить категорию без подкатегорий» — его нет у Anki.
6. Не менять: историю повторений, оценки FSRS, экран «Граф», экран «Заметки» (для него нет скриншота — не специфицирован).
7. Режимы «за порогом» (второй приоритет, не сейчас): подборки «К повторению сегодня» и «Недавно добавленное», иерархия в UI, обзорный экран категории, пресеты FSRS per-категория, теги + фильтры по ним.
