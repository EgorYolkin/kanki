# Автоподпись Kanki для личного устройства

[scripts/personal_team.py](scripts/personal_team.py) пересобирает Kanki на Mac с автоматической подписью Xcode и переустанавливает его на **собственный** iPhone/iPad. Это способ обновить бесплатный provisioning profile Personal Team, а не обход семидневного срока или 2FA. Руководство зависит от [PR #44](https://github.com/EgorYolkin/kanki/pull/44): до его слияния команды доступны в ветке `feature/personal-team-refresh`.

## Перед запуском

- Установите Xcode и откройте его хотя бы один раз. Примите лицензию **лично** и войдите под своим Apple Account в Xcode → Settings → Accounts. Убедитесь, что для аккаунта доступна Personal Team; если Xcode запрашивает 2FA, подтвердите её вручную.
- Подключите устройство к Mac по USB, разблокируйте его, подтвердите доверие/Developer Mode и проверьте доступность через `xcrun devicectl list devices`. Возможна настройка сопряжения по Wi-Fi, но Mac и устройство должны видеть друг друга в момент установки. Симулятор не подходит.
- Узнайте 10-символьный **Team ID** выбранной команды в Xcode → Settings → Accounts, а **UDID** — из `xcrun devicectl list devices`. Не публикуйте UDID и логи с личными данными в issue/PR. Выберите постоянный bundle ID, например `app.kanki.ios`; при смене ID iOS воспринимает приложение как новое и прежний контейнер данных к нему не относится.
- Выполняйте команды из корня репозитория. Нужны `python3`, `xcodebuild`, `codesign`, `security`, `xcrun devicectl` и `launchctl` (для фонового режима). Скрипт не принимает пароль Apple ID и не работает на Linux.

## Первая установка и ручное обновление

```bash
TEAM_ID=XXXXXXXXXX                  # замените своим Team ID
UDID=00000000-0000000000000000     # замените UDID доступного физического устройства
BUNDLE_ID=app.kanki.ios            # не меняйте между обновлениями
python3 scripts/personal_team.py refresh \
  --team-id "$TEAM_ID" --device-id "$UDID" --bundle-id "$BUNDLE_ID" --force
```

`refresh` проверяет, что `devicectl` видит указанное физическое iOS-устройство, затем запускает Debug-сборку `Kanki` с `-allowProvisioningUpdates`, разрешает регистрацию устройства в Xcode и передаёт `DEVELOPMENT_TEAM`, `PRODUCT_BUNDLE_IDENTIFIER`, `CODE_SIGN_STYLE=Automatic`, `CODE_SIGNING_ALLOWED=YES` **только для этой сборки**. После сборки проверяет подпись и встроенный профиль: Team ID, UDID, App ID и срок действия более суток. Только после проверки запускает `devicectl device install app`; успешное время записывается только после успешной установки. Настройки подписи симулятора в `project.yml` не меняются.

Без `--force` повторный `refresh` пропускает сборку в течение пяти суток после последней успешной установки **для той же комбинации Team ID, UDID и bundle ID**. Используйте `--force` для немедленной переустановки — например, после изменения кода, удаления приложения или восстановления доступа к устройству. Запуск команды не удаляет данные приложения; прежде чем менять bundle ID или удалять приложение вручную, сделайте резервную копию важных данных.

## Необязательное обновление через LaunchAgent

Сначала убедитесь, что ручной `refresh --force` прошёл успешно. Затем установите агент:

```bash
python3 scripts/personal_team.py install-agent \
  --team-id "$TEAM_ID" --device-id "$UDID" --bundle-id "$BUNDLE_ID"
```

Агент запускается при загрузке пользовательской сессии и ежедневно в **09:00 по времени Mac**. После успеха он пропускает попытки в течение пяти суток; после ошибки пробует снова при следующем запуске. Параметры сохраняются в `~/Library/LaunchAgents/app.kanki.personal-team-refresh.plist` как аргументы командной строки — Team ID, UDID и bundle ID, **не пароль**. Скрипт должен остаться по прежнему пути в репозитории: агент вызывает его по абсолютному пути. После переноса репозитория или смены параметров удалите и установите агент заново.

```bash
python3 scripts/personal_team.py uninstall-agent
```

`uninstall-agent` выгружает задачу и удаляет только её plist; приложение на устройстве и его данные не затрагиваются. Логи: `~/Library/Logs/Kanki/personal-team.log` и `~/Library/Logs/Kanki/personal-team-error.log`. Время последнего успеха: `~/Library/Application Support/Kanki/PersonalTeam/`; удалять или редактировать отметку вручную не требуется — используйте `--force`.

## Если обновление не получилось

| Сообщение / ситуация | Что проверить |
| --- | --- |
| Устройство не найдено или недоступно | Подключение USB/Wi-Fi, разблокировку, доверие Mac, Developer Mode и вывод `xcrun devicectl list devices`. Если устройство отключено, агент повторит попытку позднее. |
| Xcode сообщает об учётной записи, лицензии или provisioning | Войдите в Xcode, завершите 2FA, лично примите лицензию, проверьте выбранную Personal Team и возможность установки приложения на это устройство. Затем повторите `refresh --force`. |
| Неверный Team ID, UDID, App ID или истекающий профиль | Сверьте параметры и настройки подписи в Xcode. Скрипт не установит сборку с неподходящим профилем и не отметит её успешной. |
| Сборка прошла, но `devicectl` не установил приложение | Проверьте состояние и свободное место устройства, затем повторите `refresh --force`. Успешная отметка не обновляется при ошибке установки. |
| Код изменён, а агент пишет «Переподпись пока не нужна» | Это ожидаемо в первые пять суток после успешной установки: запустите `refresh --force` вручную. |

Скрипт возвращает код `0` при успешной установке **или** когда обновление ещё не требуется, и `1` при ошибке. Сообщение «LaunchAgent установлен» подтверждает только регистрацию задачи, **не** успешную установку приложения. Если Mac выключен, устройство недоступно или Xcode требует интерактивного входа, фоновое обновление не гарантируется.

## Ограничения и статус проверки

По [правилам Apple](https://developer.apple.com/help/account/basics/about-your-developer-account/) профиль бесплатной Personal Team действует **7 дней**; его нужно периодически обновлять переустановкой. Бесплатная учётная запись ограничивает число устройств и приложений и не даёт TestFlight или всех capabilities. Скрипт не подходит для распространения приложения тестировщикам, не обходит ограничения Apple и не подписывает на сервере без Mac. Отправка уведомлений в Telegram не реализована.

Синтаксис и моделируемые сценарии успеха/ошибки проверены тестами скрипта; **реальная подпись и установка на устройстве пока не подтверждены**: физическое устройство было недоступно. Проверка на личном устройстве отслеживается в [issue #43](https://github.com/EgorYolkin/kanki/issues/43).
