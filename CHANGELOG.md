# История изменений

Записи отражают только изменения, уже присутствующие в ветке; запланированные функции перечислены в [плане](tasks/plan.md) и [issues](https://github.com/EgorYolkin/kanki/issues), а не в истории релизов.

## Не выпущено

### Добавлено

- SwiftUI-оболочка iOS 17+: вкладки «Обучение», «Заметки», «Граф», «Настройки» и переходы к экранам-заготовкам. Данных, повторения и синхронизации пока нет.
- Пробные карточки в текущем сеансе: после показа ответа кнопки «Снова», «Трудно», «Хорошо», «Легко» записывают оценку с временем и возвращают к списку. Без сохранения между запусками и без расчёта SRS.
- Страница настроек: тема «Системное / Светлое / Тёмное» применяется сразу и сохраняется между запусками; честный статус неподключённой синхронизации, пояснение о сеансовых данных и версия/сборка из Info.plist.
- Экран повторения для карточек сеанса: очередь по одной карточке, скрытый до запроса ответ, переход к следующей после оценки и итог с разбивкой по оценкам. Данные и оценки не сохраняются.
- Иконка Kanki из предоставленного изображения: iPhone/iPad 1024 px и комплект прозрачных размеров macOS для будущего macOS target.
- Конфигурация XcodeGen (`project.yml`) и план восьми этапов в `tasks/`.
- Запуск на подключённом iPhone: в `project.yml` подпись отключена только для симулятора, поэтому device-сборка подписывается автоматически и Run из Xcode больше не падает с «The executable is not codesigned». Team ID, UDID и профили в репозитории не хранятся.
- Контур качества: unit-test target `KankiTests` (27 тестов), порог покрытия 95 % по `Kanki/Domain` через `scripts/coverage_gate.py`, SwiftLint в строгом режиме, markdownlint для всей документации и GitHub Actions workflow с заданиями Markdown, SwiftLint и сборка/тесты/покрытие/UI.
- Единые правила разработки: `docs/quality-gates.md` и `AGENTS.md` в каждом каталоге (`Kanki/`, `Kanki/Domain/`, `Kanki/Views/`, `KankiTests/`, `KankiUITests/`, `scripts/`, `.github/`, `docs/`, `tasks/`, `experiments/`).
- Доменная логика вынесена из `KankiApp.swift` в `Kanki/Domain/` (`Destination`, `AppAppearance`, `RecallRating`, `SessionCard`, `SessionReview`, `CardDraft`, `SessionLog`, `ReviewSessionState`), экраны — в `Kanki/Views/`; поведение и тексты не изменились.
- macOS-версия Kanki из того же кода: таргет объявлен как `supportedDestinations: [iOS, macOS]`, приложение собирается нативно (`LSApplicationCategoryType`, bundle ID `app.kanki.macos`, ad-hoc подпись без Team ID), открывается окном 900×640 и переключает разделы по ⌘1–⌘4 из меню. Добавлены macOS UI-тест `KankiMacUITests`, скрипт `scripts/macos-ui-test.sh` и задание macOS в CI. Это оболочка этапа 1: заметок, графа, редактора, SRS и синхронизации на macOS пока нет.
- Правила поведения и участия (`CODE_OF_CONDUCT.md`, `CONTRIBUTING.md`, `AGENTS.md`), шаблоны задач агента, GitHub issue и PR.
- Gitflow: рабочие ветки от `dev`, PR в `dev`, выпуск через PR `dev` → `main`.
- Локальный CLI для пересборки и переустановки Kanki с автоматической подписью Xcode для собственного устройства Personal Team; необязательный LaunchAgent проверяет необходимость обновления ежедневно и повторяет после ошибок. Пароли и ключи не хранятся; реальная установка требует настройки аккаунта и доступного устройства ([issue #40](https://github.com/EgorYolkin/kanki/issues/40)).

### Проверка и ограничения

- `./scripts/ci.sh` на этом Mac (Xcode 27.2, iPhone 17e Simulator iOS 26.3.1): линтеры без нарушений, 27 unit-тестов и покрытие `Kanki/Domain` 100 % при пороге 95 %, четыре iOS UI-теста и один macOS UI-тест прошли. macOS-приложение собрано `-destination 'platform=macOS'` и подписано ad-hoc; вход в аккаунт разработчика для macOS не требуется.
- Скелет, пробные карточки и оценки собраны и проверены на iPhone 17e Simulator (iOS 26.3.1): UI-тесты прошли; отсутствие сохранения карточек и оценок после перезапуска проверено. Этап 1 завершён, [issue #2](https://github.com/EgorYolkin/kanki/issues/2) закрыт.
- Эксперимент Э1: скрипт на backend Anki 26.09.3 проверил импорт, два повторения Good, современный `.apkg` (`collection.anki21b`), обновление без потери revlog/due/interval, повторный импорт без дублей и конфликт смены нотетайпа. Визуальный прогон и обратный конвертер в БД Kanki не выполнены; состав нотетайпа не закреплён ([issue #3](https://github.com/EgorYolkin/kanki/issues/3)).
