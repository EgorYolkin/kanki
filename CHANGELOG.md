# История изменений

Записи отражают только изменения, уже присутствующие в ветке; запланированные функции перечислены в [плане](tasks/plan.md) и [issues](https://github.com/EgorYolkin/kanki/issues), а не в истории релизов.

## Не выпущено

### Добавлено
- SwiftUI-оболочка iOS 17+: вкладки «Обучение», «Заметки», «Граф», «Настройки» и переходы к экранам-заготовкам заметок. Импорта заметок и синхронизации пока нет.
- Локальные карточки: после показа ответа кнопки «Снова», «Трудно», «Хорошо», «Легко» сохраняют каждую оценку с идентификатором карточки и временем между запусками. История видна в карточке; SRS не рассчитывается.
- Страница настроек: тема «Системное / Светлое / Тёмное» сохраняется между запусками; честный статус неподключённой синхронизации и локальных данных.
- Экран повторения: очередь по одной карточке и итог текущего сеанса; оценка сохраняется только после успешной записи. Экспорт выбранных карточек или всех сразу через отдельное меню «Экспорт» и системный файловый диалог в JSON (не `.apkg`).
- Иконка Kanki из предоставленного изображения: iPhone/iPad 1024 px и комплект прозрачных размеров macOS для будущего macOS target.
- Конфигурация XcodeGen (`project.yml`) и план восьми этапов в `tasks/`.
- Запуск на подключённом iPhone: в `project.yml` подпись отключена только для симулятора, поэтому device-сборка подписывается автоматически и Run из Xcode больше не падает с «The executable is not codesigned». Team ID, UDID и профили в репозитории не хранятся.
- Правила поведения и участия (`CODE_OF_CONDUCT.md`, `CONTRIBUTING.md`, `AGENTS.md`), шаблоны задач агента, GitHub issue и PR.
- Gitflow: рабочие ветки от `dev`, PR в `dev`, выпуск через PR `dev` → `main`.
- Локальный CLI для пересборки и переустановки Kanki с автоматической подписью Xcode для собственного устройства Personal Team; необязательный LaunchAgent проверяет необходимость обновления ежедневно и повторяет после ошибок. Пароли и ключи не хранятся; реальная установка требует настройки аккаунта и доступного устройства ([issue #40](https://github.com/EgorYolkin/kanki/issues/40)).
- Экспериментальный обратный импорт `.apkg` в изолированную SQLite-БД: контент заметок, канонические/обратные связи и прогресс по `(guid, ord)`; не является схемой или импортёром приложения.

### Проверка и ограничения
- Скелет проверен на iPhone 17e Simulator (iOS 26.3.1); отсутствие сохранения в исходном этапе 1 заменено локальным хранением карточек и оценок ([issue #60](https://github.com/EgorYolkin/kanki/issues/60)). Юнит-тесты проверили историю после повторного открытия, фильтрацию JSON и ошибки диска; UI-тесты проверили историю после перезапуска и системные диалоги выборочного/полного экспорта. SRS, сервер и совместимый экспорт Anki не реализованы.
- Эксперимент Э1: backend Anki 26.09.3 проверил импорт, два повторения Good, современный `.apkg` (`collection.anki21b`), обновление без потери revlog/due/interval, повторный импорт без дублей и конфликт смены нотетайпа. Обратный импорт в экспериментальную БД восстановил два UID, четыре ребра и две записи повторов; визуальный полный прогон в AnkiDesktop и продуктовый конвертер в БД Kanki не выполнены, состав нотетайпа не закреплён ([issue #3](https://github.com/EgorYolkin/kanki/issues/3)).
