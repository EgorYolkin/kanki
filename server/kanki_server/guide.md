# Kanki API

Чтобы добавить карточки в «Обучение», измените **снимок**. Чтобы передать
заметки в Anki, используйте **публикацию и экспорт**. Это разные операции:
публикация не добавляет ручную карточку в снимок, а экспорт `.apkg` не сохраняет
его историю повторений.

## Перед каждой задачей

1. Возьмите `KANKI_SERVER_URL` из настроек пользователя. Это адрес сервера
   без `/v1`, например `https://example.org` (демо). Сделайте новый
   `GET /v1/guide.md` на этом же адресе **без токена**. Прочитайте ответ `200`
   типа `text/markdown` с заголовком `# Kanki API`. Если руководство недоступно
   или ответ не тот, остановитесь. Не используйте старую копию, другой сервер
   или перенаправление. Это правило действует и при работе через MCP.
2. Для личных данных используйте отдельный токен устройства или агента из
   `KANKI_TOKEN`. Передавайте его только своему настроенному серверу по HTTPS
   в заголовке `Authorization: Bearer …`, не в URL. Если токена нет, попросите
   владельца настроить его безопасно; не запрашивайте токен администратора.
3. Проверьте `/v1/me`: ожидаются метка нужного токена и роль `device`.
   Например, при уже заданных переменных окружения:

   ```sh
   curl --fail --silent --show-error "${KANKI_SERVER_URL%/}/v1/me" \
     --header "Authorization: Bearer $KANKI_TOKEN"
   ```

Токены дают доступ к **одной общей коллекции** сервера, а не к разным профилям.
Не помещайте токены, содержимое снимков, публикаций и резервных копий в чаты,
логи, задачи или коммиты. Все данные в примерах ниже синтетические.

## Маршруты

| Запрос | Доступ | Результат при успехе |
| --- | --- | --- |
| `GET /v1/guide.md` | Публичный | Это руководство, без данных коллекции. |
| `GET /v1/health` | Публичный | `{status, version, time}`, `status` равен `ok`. При недоступной БД: `503 database_unavailable`. |
| `GET /v1/me` | Токен | `{label, role}`; роль `device` или `admin`. |
| `GET /v1/snapshot` | Токен | Полный снимок с ревизией и заголовком `ETag`. |
| `PUT /v1/snapshot` | Токен | Атомарная замена, `200` с полным новым снимком. |
| `POST /v1/statistics/events` | Токен | Приём пакета событий, `204` без тела. |
| `GET /v1/statistics` | Токен | Сводка посещений и оценок. |
| `POST /v1/publish` | Токен | Публикация заметок, `200` с их идентификаторами. |
| `GET /v1/export.apkg` | Токен | Все опубликованные заметки одним файлом Anki. |
| `POST /v1/tokens` | Только `admin` | `{"label":"Демо"}` (1–64 символа) → `201` с `{id, label, token}`. Секрет возвращается только при создании. |
| `GET /v1/tokens` | Только `admin` | Массив `{id, label, created_at, revoked_at}` без секретов. |
| `DELETE /v1/tokens/{token_id}` | Только `admin` | Отзыв по `id`, `204`; неизвестный или уже отозванный ID: `404 token_not_found`. |

В запросах с телом используйте `Content-Type: application/json` и UTF-8.
Коды вроде `invalid_token` находятся в `detail.code`. При `401 missing_token`
или `401 invalid_token` проверьте настройки; отозванный токен тоже недействителен.
Административные маршруты могут быть закрыты извне. `403 admin_required`
означает недостаточную роль; `503 admin_disabled` означает, что управление
токенами отключено. Для работы с коллекцией эти маршруты не нужны.

## Как изменить снимок без потери чужих правок

1. Прочитайте снимок **один раз на всю партию**. Ответ содержит `revision`,
   `schema_version`, `data`, `updated_at`. Только ответ
   `{"revision":0,"schema_version":1,"data":null,"updated_at":null}` означает,
   что снимка ещё нет. Ошибка чтения не означает пустую коллекцию. Для проверки
   уже известной ревизии можно передать её `ETag` (например, `"8"`) в
   `If-None-Match`; совпадение даёт `304` без тела. Поддерживаются также слабый
   тег и `*`. Чтобы получить данные, читайте без условия.
2. Проверьте обе версии и структуру `data`. Сохраните исходный снимок для
   сравнения. Назначьте новым карточкам и урокам UUID и время создания один раз
   на всю операцию. В копии полученного `data` измените только заказанные поля.
   Сохраните остальные поля, порядок, прежние ID, архив, переименования,
   историю `reviews` и расписания `schedules`.
3. Отправьте **один PUT**, даже если карточек пятнадцать. В теле укажите
   `schema_version: 1`, `base_revision` из GET и **полный** изменённый `data`.
   Успех возвращает ту же форму, что и GET, с увеличенной ревизией. Сервер не
   объединяет поля и не проверяет формат карточек. Он проверяет версию конверта,
   неотрицательную базовую ревизию и размер: по умолчанию до 10 МиБ для `data`
   в компактном JSON UTF-8. Слишком большой снимок даёт `413 snapshot_too_large`,
   неверный конверт даёт `422`.
4. При `409` (например, `{"detail":{"code":"revision_conflict","current_revision":9}}`)
   **или потере ответа** снова прочитайте снимок и проверьте версии. Сравните
   исходное состояние, намерение и свежие данные по сохранённым UUID. Если всё
   уже применено, второй PUT не нужен. Иначе перенесите только недостающие
   изменения на свежие данные и используйте их ревизию. Если то же поле
   независимо изменено или нужный существовавший объект исчез, остановитесь и
   сообщите о конфликте. Не отправляйте старое тело с новой ревизией и не
   восстанавливайте удалённое по совпадению текста.

Приложение сверяется с сервером при активации, не непрерывно. Для явного
чтения в настройках есть «Загрузить с сервера». Успех PUT подтверждает запись
на сервере, но не означает, что телефон уже применил изменения.

### Версии и первый урок

`schema_version` конверта равна `1`. Внутри `data.snapshot_version` допустимы
версии 1–4. Отсутствующую внутреннюю версию приложение читает как v3.
В v1 могло не быть категории, в v2 появились категории и `deck_renames`,
в v3 появился архив. В старых данных отсутствие `isArchived` означает `false`.
Чтение само по себе ничего не мигрирует. При обычной правке данных до v3
пишите v3, не включая уроки. Начальное `data` **только для пустого сервера**:

```json
{"snapshot_version":3,"cards":[],"reviews":[],"schedules":{},"deck_renames":[]}
```

Первый урок включите вместе с `snapshot_version: 4` в одной записи. До этого
сохраните полный ответ GET с ревизией в отдельную защищённую копию и убедитесь,
что **все** записывающие приложения и агенты поддерживают v4. Пока остался
клиент v3, добавляйте обычные карточки и Markdown без уроков. В v4 `lessons`
обязателен, даже когда последний урок удалён (`[]`); не понижайте версию.
`lessons` в старом формате, неверный массив в v4, невалидные ссылки, повтор
UUID карточки или неизвестная версия конверта либо данных требуют остановки,
в том числе при повторной попытке. Не объединяйте разные ключи `schedules`,
если они обозначают один UUID в разном регистре.

Пример полного тела PUT **для пустого демосервера** с первой карточкой и уроком.
Для непустого сервера не используйте его как основу: начните с ответа GET.

```json
{
  "schema_version": 1,
  "base_revision": 0,
  "data": {
    "snapshot_version": 4,
    "cards": [{
      "id": "72F6ED4C-0702-4A14-8E8F-A77E678C4410",
      "createdAt": "2026-11-19T10:00:00Z",
      "question": "Как записать список в Markdown?",
      "answer": "- Первый пункт\n- Второй пункт",
      "deck": "Разметка",
      "isArchived": false
    }],
    "reviews": [],
    "schedules": {},
    "deck_renames": [],
    "lessons": [{
      "id": "307508BC-A613-483E-AC7B-2288A5AB93EF",
      "createdAt": "2026-11-19T10:00:00Z",
      "title": "Списки",
      "course": "Редактор",
      "source_url": "https://example.org/video/1",
      "card_ids": ["72F6ED4C-0702-4A14-8E8F-A77E678C4410"]
    }]
  }
}
```

### Карточки, категории и уроки

- **Текст.** `question` и `answer` должны содержать непустой текст. Сохраняйте
  исходный Markdown: заголовки, абзацы, списки, выделение, код, абсолютные
  HTTP(S)-ссылки. Вопрос и ответ хранятся строками, не HTML. Сохраняйте отступы,
  пустые строки и последний LF. Создавайте строки с настоящим переводом строки
  и сериализуйте один раз: JSON `"a\nb"` декодируется в две строки, `"a\\nb"`
  даёт одну строку с буквальными `\` и `n`. Синхронизация и экспорт не снимают
  экранирование повторно. Не заменяйте `\n` глобально: это может быть путь или код.
- **Прогресс.** При правке сохраняйте `id` и `createdAt` (новые даты в UTC,
  ISO 8601 до секунд). `reviews` хранит оценки `{cardID, rating, reviewedAt}`;
  `schedules` хранит состояние FSRS по UUID карточки. Не исправляйте их ради
  «очистки» и не создавайте расписание новой карточке: оно появится при оценке.
- **Категория.** У карточки один `deck`: отсутствие, `null` или пустая строка
  после удаления краевых пробелов означают «Без категории». Не записывайте это
  служебное название. Для существующей категории копируйте написание с учётом
  регистра. Отдельного справочника нет. Вложенность задают названия вроде
  `Язык::Глаголы`; создавайте их только по запросу. Выбор родителя включает
  подкатегории. Перенос карточки меняет лишь `deck`, без записи о переименовании.
- **Переименование и удаление категории.** Выберите свободное непустое имя.
  Обновите `deck` у всех карточек, включая архивные: точное имя замените целиком,
  у потомков замените только префикс до `::`. Добавьте пару `{"from":"Язык","to":"Речь"}`
  в `deck_renames` (прежнюю запись с тем же `from` замените; остальные сохраните).
  При удалении категории очистите `deck` у прямых участников, а у потомков
  уберите префикс: при удалении `Язык` название `Язык::Глаголы` станет `Глаголы`.
  Карточки, курсы и уроки при этом не удаляются.
- **Выбор урока.** Курс обозначает источник, `deck` обозначает тему. Если дан
  UUID урока, ищите именно его; если не найден, уточните задачу. Иначе выберите
  точную пару `(course, title)` после удаления краевых пробелов, с учётом
  регистра. Пара и UUID урока уникальны. `title` непустой. Пустой курс
  представьте отсутствующим полем или `null`, не строкой «Без курса».
  Одноимённые уроки разных курсов не объединяйте. Для `source_url` допустим
  абсолютный HTTP(S)-адрес с именем хоста; поле необязательно.
- **Карточки видео.** Создайте один урок или дополните найденный. Сохраните
  карточки в `cards`, а их UUID добавьте в `card_ids` урока в порядке видео.
  Пустой урок допустим. Каждый ID должен существовать и входить в урок не более
  одного раза. Одну карточку можно включить в несколько уроков с тем же ID,
  расписанием и историей. Если при повторном чтении кто-то уже создал урок по
  той же запрошенной паре, используйте созданный им урок. Проверьте отдельно
  подготовленные UUID карточек и их членство: допишите только недостающие связи,
  не переставляя чужие. Не ищите дубли по тексту вопроса.
- **Архив и удаление.** Чтобы убрать карточку из повторения, предпочтите
  `isArchived: true`: сохранятся история, расписание и членство в уроках,
  но карточка исчезнет из очереди и счётчиков категорий. Занятие по уроку
  включает все его активные карточки, даже с будущим сроком. Для явно запрошенного
  физического удаления уберите в одном PUT карточку, все оценки по `cardID`,
  её расписание и ID из **каждого** урока. Удаление самого урока, напротив,
  убирает только запись из `lessons`, оставляя карточки и прогресс.

## Посещения и статистика

Для регистрации посещений и новых оценок импортированных карточек отправьте
JSON в `/v1/statistics/events`, от 1 до 100 событий, до 256 КиБ на всё тело:

```json
{"events":[
  {"id":"924e39ae-2aad-4208-80bd-990d881b09ee","kind":"visit","timestamp":"2026-11-19T08:00:00Z"},
  {"id":"b6934dbf-bec1-466e-89ed-57910e808855","kind":"imported_review","timestamp":"2026-11-19T08:01:00Z","rating":3,"topic":"Разметка"}
]}
```

`timestamp` включает дату, время и часовой пояс (ISO 8601). У `visit` нет
оценки и темы. У `imported_review` обязательна целая `rating` от 1 до 4;
`topic` необязательна, до 256 символов. Не переносите сюда старый журнал Anki
и не дублируйте оценки ручных карточек: они уже есть в снимке.
Назначайте UUID событию один раз: первая запись сохраняется, повтор с тем же ID
не меняет её даже от другого устройства. Успех `204` подтверждает весь пакет,
не меняя ревизию снимка. Ошибки `413 statistics_events_too_large`,
`415 expected_json`, `422 invalid_statistics_events` отклоняют пакет целиком.

К `/v1/statistics` можно добавить `?timezone=Europe/Moscow` (имя IANA, по
умолчанию `UTC`; неверное значение даёт `422`). В ответе:

- `totalReviews` и `ratings`: число оценок за всю историю и четыре счётчика
  в порядке «Снова», «Трудно», «Хорошо», «Легко» (1–4).
- `days`: 365 местных дат до сегодняшней включительно, от старых к новым.
  Для каждой возвращаются `{date, visits, reviews}`, даже если оба счётчика
  нулевые. Будущие даты не учитываются.
- `streakDays`: непрерывная серия дней с оценками по сегодня или по вчера,
  если сегодня ещё не оценивали. Одни посещения не продлевают серию.
- `topics`: пары `{name, count}` по убыванию числа оценок, при равенстве по
  имени. Для ручных оценок берётся текущий `deck` карточки, для импортированных
  берётся `topic` события; отсутствующая тема считается «Без категории».

## Публикация Markdown для Anki

В `/v1/publish` отправьте объект с единственным ключом `documents`: от 1 до 100
строк, до 1 МиБ на всё JSON-тело. Одна строка содержит целый документ. Например,
сериализуйте следующий текст как единственный элемент массива:

```markdown
---
uid: n-01900000-1234-7000-8000-000000000001
schema_version: 1
kind: fact
title: Список
question: Чем начать пункт списка?
answer: Символом дефиса и пробелом.
sources: []
relations: []
---
Пример пункта: `- текст`.
```

- `uid` заметки и `relations[].to` состоят из `n-` и канонического UUIDv7
  в нижнем регистре. Это не UUID ручной карточки. `schema_version` равна
  целому `1`, `kind` принимает `concept`, `fact` или `source`. Нужны непустые
  `title` и текст заметки: после блока YAML **либо** в поле `body` внутри него.
  `question` и `answer` обязательны, но здесь допустимы пустые строки.
- `sources` и `relations` обязательны, в том числе если пусты. Для источника
  задайте непустой `ref`, при необходимости строку `locator`. У связи укажите
  тип `t` (`requires`, `part_of`, `related` или `contrast`) и целевой `to`;
  можно добавить строку `note`. Цель можно опубликовать позже. Пропускайте
  необязательные поля вместо YAML `null`. Лишние поля, повторяющиеся ключи,
  YAML-алиасы и повторы `uid` в одном пакете недопустимы.
- При успехе `notes` содержит для каждого документа `{uid, guid, mod}` в
  исходном порядке. Повтор тех же разобранных данных не меняет запись. Правка
  по тому же UID заменяет всю заметку, сохраняя GUID и увеличивая `mod`.
  Пропущенные в запросе заметки не удаляются. Пакет записывается целиком либо
  никак. Возможны `422 invalid_publication` для конверта; `422 invalid_document`
  и `422 duplicate_uid` с `detail.document_index` (от нуля); `409 guid_conflict`
  для коллизии GUID; `413 publication_too_large` и `415 expected_json`.

Скачайте `/v1/export.apkg` с тем же заголовком авторизации. Успех: `200`,
`application/zip`, имя вложения `kanki.apkg`; при отсутствии публикаций:
`404 no_publications`. Файл содержит по одной новой карте (`ord=0`) на заметку,
без медиа, истории и расписания Anki. Это не синхронизация прогресса: сервер
не получает оценки из Anki при импорте файла и не объединяет их со снимком.

## Инструменты и границы

REST доступен обычному HTTP-клиенту. Установленный `kanki-mcp` работает по
stdio с переменными `KANKI_SERVER_URL` и `KANKI_TOKEN`. Он предоставляет
`health()`, `me()`, `get_snapshot()` и `put_snapshot(base_revision, data)`.
Для записи передавайте ревизию из `get_snapshot()` и полный объект `data`.
У MCP нет отдельного инструмента для руководства, статистики, публикации или
экспорта: используйте соответствующий HTTP-маршрут. У ручных карточек, курсов,
категорий и уроков нет отдельных маршрутов поиска или записи. Частичных
обновлений, обмена дельтами и автоматического разрешения конфликтов нет.
